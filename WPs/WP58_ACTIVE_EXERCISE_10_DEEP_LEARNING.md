## Notebook content and student activities

The lecture already introduces layers, dense networks, losses, epochs, training loops, tensors and batches. Keep the notebook concise and hands-on, with the same restrained language, headings, reflection prompts, and `show_question(id)` convention as current exercises. Questions should have a fixed once-per-question option shuffle with hidden keys in ordinary student view. No visible student cell should include a complete solution as commented code. Keep one honest, runnable teacher-filled/reference copy private and outside the published notebook.

1. **Setup and task.** Explain that the task is ABIDE-II autism/control classification from multiple structural MRI measures. Give ready-to-run imports and data loading. Make Python/PyTorch installation conditional for Colab/local use (`%pip` only where needed); avoid repeated installs and vague `pip install -r requirements.txt` directions in student-facing content. Verify compatibility in a fresh Colab session later with the course author; label real-Colab verification pending if access is unavailable. Show `X` shape, target counts, class balance and imaging feature-family counts.
2. **Hold-out design and tensors.** Supply a reproducible, stratified train/validation/test participant split. Fit missing-value handling and feature scaling only on training rows, transform validation/test with those fitted steps, and retain untouched test rows until final evaluation. Ask students to turn the arrays/labels into `float32` PyTorch tensors of documented dimensions, form `TensorDataset`/`DataLoader` with a given batch size (for example, 64), and inspect a batch. Include a helpful check of shapes, dtypes, label coding and finite values; avoid a cascade of red exceptions when a student has not filled a blank.
3. **Build a fully connected network.** Guide students through an `nn.Module` with input dimension inferred from `X_train`, one or two modest hidden layers, nonlinear activation and one output logit. Divide work so they write meaningful pieces (layers and `forward`) without a commented full answer. Give a concise explanation of logits, `BCEWithLogitsLoss`, and a chosen optimizer; do not apply a sigmoid before this loss. Explain the role of forward pass, loss, gradient reset, `backward()`, optimizer step, and `model.train()`/`model.eval()`.
4. **Train and validate.** Students complete the key missing lines of a training epoch and evaluation loop, with brief directional hints. Supply ready-to-run orchestration afterward using their functions: fixed seeds where practical, CPU-compatible settings, bounded epochs (for example, 30–50), small batches, validation monitoring and a simple early-stopping rule restoring the best validation weights. Train once per normal run, not on every interactive control change. Show train/validation loss curves. Student checks should give actionable feedback. Measure wall time for the **complete teacher-filled run on CPU**, from data loading through plots and checks; target comfortably under 15–20 minutes, and report actual environment/cold-start caveats.
5. **Final evaluation and comparison.** Predict probabilities and labels on test once after all choices are fixed. Show confusion matrix, accuracy, balanced accuracy, sensitivity, specificity and ROC AUC (where defined), with class counts and an appropriate simple/dummy baseline. On the same participants and same expanded feature families, fit a training-only-preprocessed regularized logistic-regression baseline so the comparison tests the model rather than the dataset. Optionally label the earlier <60% exercise result as context, never as a directly controlled comparison. Plot the learning curves and one compact comparison figure/table. Do not claim a neural-network advantage or target >60% by selecting a lucky test seed; if performance is weaker, report it honestly and explain why more features and model capacity can overfit this sample. Hyperparameter changes must use validation only; keep the test untouched.
6. **Interpretation and limits.** Ask several checked questions about tensor shape, logits/loss, gradient update, train-only scaling, overfitting/early stopping, and why test data cannot choose epochs. Add a brief wrap-up: networks can model nonlinear interactions and scale with sufficient useful data, but this cohort is small and heterogeneous, so quality, site/scanner effects and acquisition/motion QC can limit generalization. Cite relevant primary ABIDE structural harmonization/site studies with exact cohort/measure qualifications; distinguish any functional-MRI motion findings from this structural table. No diagnostic or causal claim, no suggestion that model quality alone has hit a definitive ceiling.
