## `book/lite/extensions/course-toolbar/src/index.ts`

- New `interceptAutomaticKernelSelectDialog(panel)`: watches the static
  `Dialog.tracker` (a JupyterLab singleton, already shared via this
  extension's own `package.json` `sharedPackages`) for any dialog added
  while armed. On the first one seen, once its rendered header text
  (`.jp-Dialog-header`, read via the new `waitForHeaderText()` helper --
  see below) reads exactly "Select Kernel", calls the dialog's own public
  `reject()` -- the same effect as clicking Cancel, a safe no-op from
  `SessionContextDialogs.selectKernel()`'s own perspective
  (`if (!result.button.accept) return;`). Armed synchronously as soon as
  a panel is added to `INotebookTracker` (see the `activate()` change
  below); disarms itself (stops listening) the first time the kernel's
  own `statusChanged` fires anything other than
  `starting`/`unknown`/`restarting`/`autorestarting`
  (`KERNEL_NOT_YET_STARTED_STATUSES`), with a 60-second hard ceiling
  (`DIALOG_GUARD_TIMEOUT_MS`) as a safety net if that never happens.
- New `waitForHeaderText(node, timeoutMs)`: `Dialog`'s own `ready`
  promise only tracks its *body* widget's React render, never its
  separately rendered header -- polls once per animation frame (not a
  fixed sleep) until the header's actual text appears, bounded by
  `HEADER_TEXT_TIMEOUT_MS` (2s).
- New `nextAnimationFrame()`: small `requestAnimationFrame`-based promise
  helper used by `waitForHeaderText()`.
- `ensureKernelStarted()`: unchanged in effect from WP55 (bounded-race
  kernel recovery), only its own interceptor-arming/-disconnecting code
  removed -- that responsibility moved entirely into
  `interceptAutomaticKernelSelectDialog()`'s own, independent lifecycle
  (see the Report's "three real mistakes" section for why coupling the
  two was wrong).
- `activate()`: `tracker.widgetAdded`'s callback now calls
  `interceptAutomaticKernelSelectDialog(panel)` synchronously, before
  the existing `panel.context.ready.then(...)` block (which still does
  `addButtons`/`addStatusReadout`/`ensureKernelStarted`, unchanged). Also
  registers `window.__courseToolbarOpenSelectKernelDialogForTest`, a
  test-only hook (not wired to any command/menu/keybinding) that opens
  the real, unmodified `SessionContextDialogs.selectKernel()` against the
  current panel's real `sessionContext`, for
  `kernel-select-dialog-race.spec.ts`'s own deterministic reproduction
  (see the Report's "Why this did not reproduce live" section for why
  the dialog's own real automatic trigger could not be driven directly).
- New import: `SessionContextDialogs` from `@jupyterlab/apputils`
  (already a shared dependency of this extension).
- Rebuilt the labextension bundle (`npx tsc && jupyter labextension
  build --development True .`) -- output is gitignored, regenerated by
  CI itself.

## New: `interactive/e2e-book/kernel-select-dialog-race.spec.ts`

Two tests:
1. A Select Kernel dialog opened (via the test-only hook) while the
   kernel has not started yet -- with Pyodide's own CDN assets
   deliberately delayed 9s so the session stays genuinely kernel-less
   for that window -- is gone again within 5 seconds, and Python still
   starts and a trivial cell still runs with zero error cells.
2. The normal, undelayed fast path never shows a Select Kernel dialog at
   all.
