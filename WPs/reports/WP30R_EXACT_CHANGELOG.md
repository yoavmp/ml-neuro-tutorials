## Modified

- `scripts/decision_tree_model_audit.py` —
  - Module docstring: added a bullet documenting that the classification-depth curve now
    reconstructs Exercise 3's exact outer `classification.holdout_split` and restricts every
    cross-validation fold to the resulting development partition, with exclusion proven by
    participant-set membership rather than by "this script never reads a stored test-index
    object" (the earlier, misleading framing this WP corrects).
  - Added `_classification_eligible_cohort(frame)`: builds the full eligible cohort's target
    encoding and stable `subject` identifiers (factored out of the old
    `_classification_complexity_curve` so the split-reconstruction helper below can share it).
  - Added `_classification_dev_test_positions(y_eligible, subjects_eligible)`: reconstructs
    Exercise 3's exact outer split (`train_test_split(test_size=0.25, random_state=42,
    stratify=y)`) over the eligible cohort, sorts the resulting positions back into original row
    order (train_test_split itself returns them pre-shuffled — necessary because
    `StratifiedKFold(shuffle=True, ...)`'s fold assignment depends on row order, not just row
    membership; this was the first, self-caught bug during this WP's own validation — see the
    report), and asserts development/outer-test participant-id sets are disjoint and their union
    equals the eligible cohort (raising `RuntimeError` otherwise).
  - Rewrote `_classification_complexity_curve(frame)`: now calls the two helpers above, restricts
    `X_dev`/`y_dev` to the development positions before ever constructing `StratifiedKFold` or
    fitting any `DecisionTreeClassifier` (the outer-test positions are used only to count labels
    and to prove disjointness — never passed to `.fit(`/`.predict(`/`roc_auc_score(`), and returns
    an expanded result dict: `n_eligible(/_positive/_negative)`, `n_development(/_positive/_negative)`,
    `n_outer_test(/_positive/_negative)`, `development_test_disjoint`,
    `development_test_union_equals_eligible`, `outer_holdout_reconstruction`
    (`test_size`/`random_state`/`stratify` echoed back), plus the unchanged `depth_grid`/
    `train_auc`/`val_auc`/`best_depth`/`margin_over_depth2`/`inclusion_rule` (same tie-break and
    inclusion-rule logic as WP30, untouched). `cv` string now says "development rows only".
  - `validate()`: added checks that `development_test_disjoint` and
    `development_test_union_equals_eligible` are both true, that
    `n_development + n_outer_test == n_eligible`, that positive-class counts partition the same
    way, and that `n_outer_test > 0` (the outer test set must be non-empty, i.e. genuinely
    excluding something) — in addition to the pre-existing fresh-recomputation check on the
    inclusion rule's three booleans (kept, now reading the corrected `val_auc` curve).
  - `_print_summary()`: now prints eligible/development/outer-test sizes alongside the existing
    best-depth/margin summary line.
