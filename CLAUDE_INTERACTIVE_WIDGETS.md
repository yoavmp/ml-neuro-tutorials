# Claude Code assignment: reusable interactive activities

Work in the existing `ml-neuro-tutorials` repository. The eventual goal is to replace the unreliable embedded `ipywidgets`/Matplotlib EDA activity with reusable browser-native activities that work directly in the static Jupyter Book published on GitHub Pages.

This assignment uses a gated work-package process. Execute **only the single currently authorized WP** named in `WPs/README.md`. After completing or failing it, write its report and stop. Yoav will return the report to ChatGPT; ChatGPT will review it and generate the next WP.

## Rules for every WP

1. Inspect the repository and preserve unrelated work. Never use `git reset --hard`, `git clean -fd`, `git checkout --`, or rewrite history.
2. Before making any WP changes, save the current state in Git:
   - inspect `git status --short`, `git diff`, and relevant untracked files;
   - exclude build output, caches, `.DS_Store`, credentials, tokens, private data, and other unsafe files;
   - if any suspicious or potentially sensitive file is present, stop and ask Yoav;
   - commit all legitimate current project changes with `checkpoint: before WPXX`;
   - if the tree is already clean, create an empty checkpoint with `git commit --allow-empty -m "checkpoint: before WPXX"`;
   - create an annotated tag `wpXX-start` at that checkpoint, adding a numeric suffix if the tag already exists.
3. Record the checkpoint hash and tag in the WP report. Do not perform a reset or revert yourself.
4. For WP01, create `feature/reusable-interactive-widgets` before the checkpoint unless already on an appropriate feature branch.
5. Do not push or merge. Local checkpoint, implementation, and report commits are authorized.
6. Do not commit `book/_build`, `.DS_Store`, virtual environments, caches, `node_modules`, test artifacts, or temporary/generated files that CI can reproduce.
7. Do not add a server-side runtime. The published GitHub Pages site must remain static.
8. The eventual embedded activities must not depend on a Python kernel, JupyterLite, Voici, widget state, or an external CDN. Existing JupyterLite support may remain for separately launching notebooks.
9. Edit notebooks with Python `nbformat`, not broad text replacement of notebook JSON. Preserve unaffected cells, cell IDs, metadata, tags, and outputs.
10. Do not silently change teaching prose or analysis results.
11. Do not download participant imaging data. Export only small required tabular fields; represent missing values as JSON `null`; avoid participant identifiers unless required.
12. Complete the specified tests. If something remains broken after reasonable diagnosis, report it honestly as partial success or failure.
13. After committing the WP report, stop. Do not draft or begin the next WP.

## Intended architecture for later WPs

The likely target is a reusable TypeScript/Vite browser application with locally bundled Plotly.js, declarative JSON configurations, pure testable calculations, and iframe embedding in Jupyter Book. WP01 must audit the real repository and confirm or amend that direction; it must not implement it.

Likely eventual source layout:

```text
interactive/
  package.json
  package-lock.json
  tsconfig.json
  vite.config.ts
  src/
  tests/
  e2e/
scripts/
  export_widget_data.py
book/_static/widgets/
  configs/
  data/
  app/                 # generated by Vite
```

Important eventual requirements:

- controls must redraw the actual graph, not only adjacent text;
- plotting and calculations must be testable independently;
- assets must work beneath the GitHub Pages repository subpath;
- runtime assets must be locally bundled, without a CDN;
- browser tests must exercise the controls on the final built Jupyter Book page.

## End-of-WP procedure

1. Commit implementation/audit changes using the WP's required message.
2. Generate `WPs/reports/WPXX_REPORT.md` using the template in `WPs/README.md`.
3. Explicitly report success, partial success, or failure and every deviation from instructions.
4. Commit the report separately with `WPXX report: document results`.
5. Print a terminal summary containing branch, checkpoint/tag, implementation commit, report commit, files changed, commands/tests, deviations, risks, and Git status.
6. Tell Yoav to paste the complete report into the ChatGPT conversation that created the WP.
7. Stop and make no further changes.
